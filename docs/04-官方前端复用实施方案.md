# 官方前端复用实施方案（授权集成路线）

> 状态：待平台授权与联调资料到位后实施
> 目标：复用平台**明确授权的测试/沙箱前端**；业务展示数据来自本地模拟器。

## 1. 结论与边界

“官方前端完全复用”不等于加载生产卖家中心后替换登录、伪造 cookie 或重写其生产接口。生产前端包含账号认证、签名、风控和持续变化的私有接口；对这些机制做中间人改写既不稳定，也会把培训系统变成凭证与会话安全风险点。

本项目采用以下边界：

| 能力 | 支持方式 |
| --- | --- |
| 官方前端复用 | 平台提供的 sandbox / staging URL、可嵌入测试包，或书面授权的本地开发构建 |
| 本地业务数据 | 本项目的 Scenario、Shop、Product、Order 数据库和 API |
| 登录 | 模拟器自身演示账号，或平台提供的**测试账号**；不收集真实生产账号密码 |
| 离线演示 | 本地实现的独立演示站点，常驻“模拟环境”水印 |
| 生产站点拦截、伪造会话、绕过鉴权 | 不实施 |

因此，在平台授权资料未到位时，P2/P3 使用本地演示站点；授权资料到位后才进入本方案的 P4。

## 2. 推荐架构

```text
授权的官方 sandbox 前端
  └─ 公开、版本化的数据提供者配置 / SDK
       └─ Simulator Adapter（字段转换、只读）
            └─ 本地 Server API + SQLite Scenario 数据
                 └─ 管理后台配置数据
```

适配器是唯一的平台差异层。它只把内部统一模型转换为平台已文档化的测试契约，不能直接依赖或猜测生产接口。

## 3. 分步实施与验收

### P1：本地数据底座（已实现，需验收）

- Prisma 数据模型、种子数据、模拟登录、页面读取 API 和后台 CRUD。
- 所有子资源写操作按 `scenarioId` 校验，禁止跨场景修改。
- 验收：登录后只能读取所属场景；尝试用另一个场景的商品/订单/账号 ID 写入，接口返回业务错误且数据不变。

### P2：本地离线演示前端

- 独立实现登录、看板、商品和订单页；不复制官方静态资源、Logo 或生产代码。
- 页面只消费 `/api/pages/*`，根组件强制渲染水印。
- 验收：后台改动数据后，刷新演示页可见变化；断网仍能完整演示。

### P3：管理后台

- 实现场景、店铺指标、商品、订单、账号、批量订单和拦截规则的管理 UI。
- 验收：不接触数据库工具即可创建一个完整、可登录的场景。

### P4：授权官方前端适配

进入条件（全部满足）：

1. 平台出具 sandbox/staging 地址或可分发的前端构建，并书面允许本地数据提供；
2. 提供版本化的接口/OpenAPI/SDK 契约、测试账号和字段说明；
3. 确认数据提供方式（环境变量、provider URL、SDK mock 或测试网关），不涉及生产请求改写；
4. 双方确认日志、数据保留、品牌标识和演示水印要求。

实施顺序：

1. 为 `mockAdapters/<siteKey>` 增加契约测试样例；
2. 实现字段映射与分页、状态、金额、时区转换；
3. 在 sandbox 环境接入本地 Adapter；
4. 做数据一致性、错误降级和版本兼容测试；
5. 记录所接入官方版本及回退版本。

验收：官方授权测试前端显示的店铺、商品、订单数字全部可从后台配置修改；断开 Adapter 时页面明确提示“演示数据服务不可用”，不会回落到真实生产数据。

## 4. 平台接入清单

每个平台在开始前必须补齐：

- 前端包/测试入口及版本号；
- 接口契约和字段枚举；
- 本地开发时的跨域、Cookie、认证约束；
- 测试账号和有效期；
- 变更通知、版本兼容与下线策略；
- 品牌素材和 UI 使用授权范围。

SHEIN 与 Amazon 均应分别走完此清单。未满足清单时，项目仅启用本地离线演示模式。

## 5. 数据映射原则

| 内部字段 | 适配器职责 |
| --- | --- |
| `Scenario` | 选择当前训练场景，绝不由前端任意切换到未授权场景 |
| `Shop.metrics` | 单位、币种、精度与时区标准化 |
| `Product` | 平台 SKU、状态和库存枚举转换 |
| `Order` | 保持商品引用、分页总数、金额及状态的一致性 |

适配器不保存真实凭据，不向日志写入密码、Cookie、Authorization 或原始请求体。
