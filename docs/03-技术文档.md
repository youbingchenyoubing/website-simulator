## 1. 系统总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ apps/client  Electron 壳浏览器（讲师/学员使用）                 │
│  - 顶部自绘 UI：地址栏、前进/后退/刷新、多标签、"模拟环境"标识     │
│  - 内置 <webview>（WebContentsView）渲染页面                   │
│  - ses.webRequest.onBeforeRequest 拦截命中域名的请求             │
│    → 重写到 http://127.0.0.1:8080/site/<siteKey>/<path>        │
│  - 未命中域名 → 本地阻断页 blocked.html                         │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTP (127.0.0.1)
┌──────────────────────────────▼───────────────────────────────┐
│ server  Node.js + Express + Prisma + SQLite                    │
│  ├─ 静态资源：apps/site/dist（模拟站点）、apps/admin/dist（后台） │
│  ├─ 模拟站点 API  /api/auth/*  /api/pages/*                    │
│  ├─ 管理后台 API  /api/admin/*                                 │
│  ├─ 拦截规则 API  /api/intercept-rules                         │
│  └─ 元信息       /api/meta（含全局水印文案）                     │
└──────────────────────────────────────────────────────────────┘
```

**进程拓扑**：单机演示只需 `node server`（或 docker compose）。客户端 Electron 为可选增强（M1 POC、M3 正式）。

**端口与绑定**：默认 `HOST=127.0.0.1`、`PORT=8080`。要开放内网访问必须显式设置 `HOST` 并在配置文件中留确认记录（合规 §2-1）。

## 2. 数据模型（Prisma / SQLite）

对应 `packages/shared/src/index.ts` 中的 TS 类型，一一映射：

| 表 | 关键字段 | 说明 |
|---|---|---|
| Scenario | id, name, site(shein/amazon), status, demoLogin | 一套完整演示数据 = 一个场景 |
| Shop | id, scenarioId, name, avatar, metrics(JSON string) | 场景内单店铺，metrics 存看板指标 |
| Product | id, scenarioId, title, sku, image, price, stock, sales, status | 商品 |
| Order | id, scenarioId, orderNo, productId?, productTitle, quantity, amount, buyer, status, createdAt | 订单 |
| MockAccount | id, scenarioId, username, password, role | 模拟登录账号；密码只校验不回传 |
| InterceptRule | id, host, site, enabled | 域名 → 站点模板映射，客户端启动时拉取 |
| AdminUser | id, username, passwordHash | 管理后台账号（seed 初始化，环境变量可覆盖） |

约束：
- 所有业务表带 `scenarioId` 索引；所有业务查询强制带 `scenarioId`（数据隔离 = 场景切换）。
- `Shop.metrics` 以 JSON 文本存储（SQLite），读侧解析、写侧整体覆盖，避免为指标单建宽表。
- 密码类字段：MockAccount 为演示数据可明文存但接口永不返回；AdminUser 存 SHA-256 加盐哈希。

## 3. API 设计

统一响应包：`{ ok: true, data: T }` / `{ ok: false, message }`，HTTP 200（业务错误不走 4xx/5xx，演示环境简化前端处理）。

认证：登录成功写内存 session（`Map<sid, payload>`），种 `HttpOnly; SameSite=Lax` cookie。**用户输入的密码不写日志、不落盘**（合规 §2-4）。

### 3.1 公共
| Method & Path | 说明 |
|---|---|
| GET /api/meta | 返回 `{ app, version, watermark }`，站点前端据此强制渲染水印 |
| GET /api/intercept-rules | 返回 `enabled=true` 的 `[{host, site}]`，供客户端使用 |
| GET /api/health | 探活 |

### 3.2 模拟站点（无需管理鉴权，session 可选）
| Method & Path | 说明 |
|---|---|
| POST /api/auth/login | `{username,password,site}`。优先命中该 site 的 active 场景下的 MockAccount；未命中时若场景 `demoLogin=true` 则放行（记 session 到该场景），否则 `ok:false`。返回场景信息 |
| POST /api/auth/logout | 清 session |
| GET /api/auth/me | 当前 session 用户 |
| GET /api/pages/dashboard?scenarioId= | 看板聚合：shop + metrics + 近30天趋势（由订单表聚合）+ 待办计数 |
| GET /api/pages/products?scenarioId=&page=&pageSize=&q= | 商品分页 |
| GET /api/pages/orders?scenarioId=&page=&pageSize=&status= | 订单分页 |

### 3.3 管理后台（需 admin session）
| Method & Path | 说明 |
|---|---|
| POST /api/admin/login / logout / GET /api/admin/me | 管理端认证（独立 session 池） |
| GET/POST /api/admin/scenarios；PATCH/DELETE /api/admin/scenarios/:id；POST /api/admin/scenarios/:id/duplicate | 场景 CRUD + 一键复制（连店铺/商品/订单/账号深拷贝） |
| GET /api/admin/scenarios/:id/overview | 场景聚合视图（店铺+商品数+订单数），后台首页用 |
| PUT /api/admin/scenarios/:id/shop | 店铺信息与 metrics 整体保存 |
| GET/POST/PATCH/DELETE /api/admin/scenarios/:id/products[/:pid] | 商品 CRUD |
| GET/POST/PATCH/DELETE /api/admin/scenarios/:id/orders[/:oid] | 订单 CRUD |
| POST /api/admin/orders/batch-generate | `{scenarioId,count,statusWeights?,dateRangeDays?}` 按权重随机生成订单（随机商品/买家/金额/时间） |
| GET/POST/PATCH/DELETE /api/admin/scenarios/:id/accounts[/:aid] | 模拟账号管理（回传不带头 password） |
| GET/POST/PATCH/DELETE /api/admin/intercept-rules[/:id] | 拦截规则管理 |

**数据实时生效（F-307）**：所有读接口直接查库，无缓存；站点前端页面级 refetch 即可。

## 4. 模拟站点（apps/site）设计

技术：React 18 + Vite + React Router + 自绘 CSS（SHEIN 卖家中心风格：黑白极简、红色点缀），不使用官方 Logo/素材（合规 §2-3）。

路由（以 `/` 为站点根，客户端拦截后把官方域名路径透传）：
- `/login` —— 登录页。布局按官方 1:1 重绘：左侧品牌区、右侧账号密码表单。提交 → `/api/auth/login`，成功后写 localStorage `{scenarioId, site}` 并跳 `/dashboard`。
- `/dashboard` —— 数据看板：指标卡（今日销售额/订单/累计/待处理）、近 30 天趋势图（SVG 自绘折线，零依赖）、待办列表。
- `/products` —— 商品列表（表格：图/标题/SKU/价格/库存/销量/状态）+ 搜索分页。
- `/orders` —— 订单列表 + 状态筛选。

**强制水印（合规 §2-2）**：`Watermark` 组件挂在应用根节点：
1. 顶部 4px 品牌条 + 右上角固定「模拟环境」徽章（`position:fixed; z-index:9999; pointer-events:none`）；
2. 右下角半透明水印文案（文案来自 `/api/meta`，服务端可配）；
业务页面无法通过 props 关闭——组件不接受关闭参数。

**数据解耦（F-206）**：页面所有业务数据只来自 `/api/pages/*`，组件内禁止写死业务数值；UI 文案（按钮名等）允许硬编码。

**多站点模板（F-205）**：`src/themes/<siteKey>/` 下放平台差异化样式/文案，接口层完全一致。本期实现 `shein`，`amazon` 预留目录与映射表。

## 5. 管理后台（apps/admin）设计

技术：React 18 + Vite + Ant Design 5（CRUD 密集型页面用 antd 成本最低）。

页面：
- 登录页（`/login`）
- 场景列表：卡片式，显示 site/状态/数据量，操作=进入配置/复制/启停/删除
- 场景配置（Tab）：
  - 店铺与指标（表单：店名、头像、各指标数值）
  - 商品管理（Table + 弹窗表单）
  - 订单管理（Table + 弹窗表单 + 「批量生成」弹窗：数量/状态权重/时间范围）
  - 账号管理（Table + 弹窗表单）
- 拦截规则管理（Table + 弹窗表单）

后台访问路径 `/admin`，与模拟站点同端口但独立 bundle、独立 session。

## 6. Electron 客户端（apps/client）设计

```
apps/client/
├── package.json          # electron, 脚本 start
└── src/
    ├── main.js           # 主进程：窗口、拦截、规则拉取
    ├── preload.js        # 暴露最小 API（无 nodeIntegration）
    ├── chrome/           # 壳 UI（地址栏/标签页）
    │   ├── index.html / renderer.js / style.css
    └── blocked.html      # 未命中域名阻断页
```

核心流程（main.js）：
1. 启动 → 创建 `BrowserWindow`（壳 UI 载入 chrome/index.html）；
2. `GET http://127.0.0.1:8080/api/intercept-rules` → 内存规则表（失败用缓存/默认表兜底）；
3. 渲染进程用 `WebContentsView`（或 webview tag）承载站点页面；其 session 上注册 `webRequest.onBeforeRequest`：
   - URL host 命中规则 → `redirectURL = http://127.0.0.1:8080<path>`，站点前端靠 localStorage 的场景上下文正常取数；
   - 未命中 → `cancel: true`，壳 UI 检测 `did-fail-load` 显示 blocked.html（F-103 默认最严策略，`WSIM_ALLOW_PASSTHROUGH=1` 可放开为透传）；
4. 地址栏仅为 UI：输入域名 → `view.webContents.loadURL('https://'+host+path)`，拦截层负责重写；地址栏旁边常驻「模拟环境」徽标（F-105）。

安全基线：`nodeIntegration:false`、`contextIsolation:true`、禁用 remote、窗口不接受外部 open-url。

## 7. 构建与部署

- 开发：`npm run dev:server`（tsx watch）+ `dev:site` / `dev:admin`（vite dev，proxy `/api` → 8080）。
- 生产：根 `npm run build` → server 静态托管 `apps/*/dist` → `node server`；或 `docker compose up`（已提供，端口映射 `127.0.0.1:8080`）。
- 客户端：`npm run dev -w @wsim/client` 本地起 Electron；分发用 electron-builder（M3 再做打包 CI）。
- 数据库：首次启动 `prisma db push` + `prisma/seed.js`（幂等：创建 admin、默认拦截规则、SHEIN 演示场景 + 示例数据）。

## 8. 方案 D：官方前端 + 数据接口拦截（双轨之第二轨）

> 决策来源：需求文档 §7（2026-10-09 补充）。与"UI 重绘"双轨并行：
> **服务端、数据模型、管理后台完全共用**，只增加一个"官方接口适配层"。

### 8.1 原理
```
Electron 加载真实官方站点（真实 HTTPS + 真实域名 + 真实证书）
  ├─ 静态资源(HTML/JS/CSS/图) → 直连官方 CDN，不做任何复制/缓存  ← 零版权问题
  └─ XHR/fetch 数据接口 → ses.webRequest.onBeforeRequest 命中规则
       → redirect 至 http://127.0.0.1:8080/mock/<siteKey>/<原路径>
       → 本地 mock 服务返回【与官方 API 同构】的 JSON              ← 数据全部可配置
```

### 8.2 技术要点
1. **重定向而非改写响应体**：Electron `webRequest` 不能修改响应体，用 `redirectURL` 把 API 请求整体重写到本地即可，能力上是标准用法。
2. **CORS / 混合内容**：mock 服务对 `/mock/*` 返回 `Access-Control-Allow-Origin: https://<官方域名>`（含 credentials）；`http://127.0.0.1` 属 potentially trustworthy origin，https 页面调用不触发 mixed-content 拦截。
3. **登录态伪造**：拦截官方登录接口返回"成功"同构响应；必要时用 `session.cookies.set` 给官方域预种会话 cookie，让后续请求通过前端自身的鉴权判断。
4. **接口指纹表**（适配层核心资产）：每个平台维护一份"路径 → 响应 schema"映射，mock 服务下的 `src/mockAdapters/<siteKey>/` 按官方格式组装数据（内部仍以我们的 Scenario/Product/Order 模型为唯一数据源，Adapter 负责翻译）。
5. **数据一致性**：Adapter 必须保证跨接口引用自洽（订单里的商品 id 在商品接口可查、分页 total 与列表长度一致等），否则官方前端渲染异常即"露馅"。

### 8.3 与方案 A 的对比与分工
| 维度 | A：重绘前端 | D：官方前端 + 接口拦截 |
|---|---|---|
| 版权 | 需自觉遵守不盗用素材 | 零复制（浏览器正常访问官网） |
| 仿真度 | 高但需持续追版 | 100%，官方改版自动跟随 |
| 主要风险 | 形似钓鱼（假域名观感） | 官方接口变更/风控指纹导致适配失效 |
| 主要工作量 | 画 UI（可控） | 逆向接口（依赖抓包，不可控部分多） |

**分工**：D 作为体验主线（验证通过后优先），A 作为离线/接口失效时的兜底。两轨共用 `Scenario → API` 数据管道。

### 8.4 POC 验证清单（方案 D，预计 2~3 天）
- [ ] Electron 打开官方登录页，拦截其登录接口返回伪造成功，页面进入登录后状态；
- [ ] 拦截看板数据接口，返回本地场景数据，官方页面正常渲染出我们的数字；
- [ ] CORS/cookie 链路通畅（无跨域报错）；
- [ ] 接口失效降级：拦截命中但本地无适配时，可选择「放行真实请求」或「显示维护页」，行为可配置。

## 9. 分阶段实施计划

| 阶段 | 范围 | 完成判据（DoD） |
