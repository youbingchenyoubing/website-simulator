# 部署与运维指南

> 适用范围：本机或已审批的内网培训环境。不得暴露到公网。

## 1. 部署前检查

- 已安装 Docker Desktop（建议）或 Node.js 22 LTS+。
- 默认仅允许宿主机访问 `127.0.0.1:8080`；如需内网演示，必须经过审批后再调整端口绑定与防火墙规则。
- 管理密码必须通过环境变量覆盖默认演示值；不要将真实账号、Cookie 或 API Token 写入配置文件。
- 先阅读 `docs/04-官方前端复用实施方案.md`：当前交付为本地模拟前端，不接入官方生产登录或私有接口。

## 2. Docker Compose（推荐）

在项目根目录执行：

```powershell
docker compose up --build -d
docker compose ps
```

访问：

- 演示站点：[http://127.0.0.1:8080/](http://127.0.0.1:8080/)
- 管理后台：[http://127.0.0.1:8080/admin](http://127.0.0.1:8080/admin)

查看启动日志：

```powershell
docker compose logs -f simulator
```

停止服务（保留数据）：

```powershell
docker compose down
```

数据库位于命名卷 `simulator-data`，容器更新或重建不会丢失。首次启动会自动执行 Prisma 建表与幂等种子。

### 覆盖默认管理密码

不要修改或提交 `docker-compose.yml` 中的默认密码。为本次部署设置进程环境变量：

```powershell
$env:ADMIN_USERNAME = 'training-admin'
$env:ADMIN_PASSWORD = '请使用高强度随机密码'
docker compose up --build -d
```

> `docker-compose.yml` 会读取当前进程环境变量。生产化部署应由受控的 `.env`（不提交）或安全的编排平台变量注入，绝不能沿用示例默认密码。

## 3. 本机 Node.js 部署

```powershell
npm ci --no-audit --no-fund --cache .npm-cache
npm run db:push
npm run db:seed
npm run build
$env:ADMIN_PASSWORD = '请使用高强度随机密码'
npm run start
```

首次运行会在 `server/data/simulator.db` 创建 SQLite 数据库。这个文件包含训练数据，不应提交到 Git。

## 4. 启动后验收

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health
```

应返回：

```json
{"ok":true,"data":{"up":true}}
```

接着访问管理后台，创建或编辑一个场景；以模拟账号登录演示端，刷新后确认指标、商品或订单变化可见。所有页面必须显示“模拟环境”标识。

## 5. 数据备份、恢复与重置

### Docker 卷备份

停止业务写入后，导出卷内容：

```powershell
docker run --rm -v simulator-data:/data -v "${PWD}:/backup" alpine tar czf /backup/simulator-data-backup.tgz -C /data .
```

恢复前先停止服务，再将备份解压回同一个卷。恢复操作会覆盖当前训练数据，应先保留一份现有备份。

### 本机 SQLite 备份

停止服务后复制 `server/data/simulator.db` 至受控备份位置即可。恢复时用备份文件替换该文件，再启动服务。

### 重置训练数据

这是破坏性操作。先备份后删除 SQLite 文件（或 Docker 卷），再执行 `npm run db:push` 和 `npm run db:seed`。不要对不明确的目录执行递归删除命令。

## 6. 配置项

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址；非回环地址会输出合规警告 |
| `PORT` | `8080` | HTTP 端口 |
| `DATABASE_URL` | 本地 SQLite | 可替换数据库位置，需保证进程可写 |
| `ADMIN_USERNAME` | `admin` | 初始管理员账号 |
| `ADMIN_PASSWORD` | `admin123` | 初始管理员密码；部署必须覆盖 |
| `DEMO_WATERMARK` | `模拟环境 · 仅供培训演示` | 页面强制水印文案 |

## 7. 故障排查

| 现象 | 排查方式 |
| --- | --- |
| `DATABASE_URL` 缺失 | 确认从项目 `server` 工作区执行命令，且 `server/.env` 存在；或显式设置环境变量 |
| 管理后台显示未登录 | 清理该浏览器站点 Cookie 后重新登录；检查服务未重启（会话存内存） |
| 页面不更新 | 刷新演示端；确认修改的是当前登录场景；查看 `/api/health` |
| 端口占用 | 更换 `PORT`，或确认旧的本地 Node/Docker 服务已停止 |
| Docker 构建失败 | 执行 `docker compose logs`，确认 Docker Desktop 已启动并能拉取 `node:22-alpine` |
